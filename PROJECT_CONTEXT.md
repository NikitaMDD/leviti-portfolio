# PROJECT_CONTEXT.md

## Цель проекта

Портфолио-сайт для диджея. Основная функция — представить артиста: кто он, что играет, где выступал, дать возможность послушать миксы и связаться по вопросам букинга.

Сайт публичный, без личного кабинета и авторизации. Контент обновляется нечасто (новые миксы, новые ивенты, фото).

## Дизайн-принципы

Референс того, как делать **не надо**: [narrowdesign.com](https://www.narrowdesign.com) — крутой дизайн-кейс сам по себе, но слишком концептуальный и непонятный для формата портфолио.

Что нужно вместо этого:
- Простая, понятная навигация — посетитель сразу понимает, что это за сайт и что тут делать
- Контент на первом плане (фото, миксы, контакты), а не экспериментальная механика взаимодействия
- Минимум когнитивной нагрузки — никаких загадочных интерфейсов, скролл-триггеров ради эффекта и т.п.

## Предполагаемая структура контента

- Главная / визитка (фото, имя, статус по букингу, соцсети)
- Миксы/треки: часть — self-hosted аудиофайлы в проекте (для этих треков работает hero-эффект, реагирующий на реальное аудио), часть — embed (SoundCloud/YouTube и т.п., остальные работы артиста)
- Галерея с ивентов
- Новости / ближайшие выступления (опционально)
- Контакты / форма букинга

## Hero-эффект (ключевая фича)

Анимированный WebGL-фон на главной странице — органичные шумовые/flow-волны (в духе mesh gradient/simplex noise), тёмный фон с оранжево-красно-бирюзовыми цветами (см. палитру ниже). В покое — медленный темп. При воспроизведении self-hosted трека — реагирует в реальном времени на звук через Web Audio API (`AnalyserNode`), модулируя параметры шейдера (скорость/интенсивность) под амплитуду/частоты. Для embed-треков остаётся в спокойном режиме (доступа к аудиопотоку iframe нет из-за CORS).

Кандидат-библиотека: `@paper-design/shaders-react` (или vanilla `@paper-design/shaders`) — готовые WebGL-шейдеры (mesh gradient, simplex noise, warp и др.), не требует написания GLSL с нуля, пропсами настраиваются цвета/скорость/дисторшн. Компонент — island (`client:load` или `client:visible`), не влияет на SSG остальной части сайта.

## Типографика

- **Archivo** (Google Fonts) — заголовки и основной текст. 800–900 uppercase для бренда/названий секций, 500–600 для абзацев
- **JetBrains Mono** — служебный слой: навигация, метаданные миксов (жанр/дата/длительность), подписи кнопок, статусы, поля формы, футер

## Технический стек

- **Astro** — статическая генерация (SSG), выбран сознательно вместо Next.js: для контентного сайта без личного кабинета SSR избыточен, а Astro отдаёт минимум JS на клиент (islands architecture), что даёт быструю загрузку и хороший SEO из коробки
- Интерактивные блоки (например, плеер миксов), если понадобятся — точечно как island-компонент (React/Vue/Svelte по необходимости)
- Хостинг: GitHub Pages + GitHub Actions (CI/CD на автодеплой) + арендованный домен

## Почему не другие варианты (кратко)

- **Vanilla HTML/CSS/JS** — минимум обучения нового, неудобно обновлять контент
- **Next.js с SSR** — избыточная сложность (нужен постоянно работающий сервер) для сайта, где контент почти статичен и нет персонализации под юзера
- **SvelteKit / Nuxt** — рассматривались как альтернативы, тоже валидны, но Astro проще стартовать и лучше заточен именно под контентные сайты
